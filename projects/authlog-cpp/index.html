C++20 / defensive log processing

A small parser. Explicit boundaries.

Detect repeated authentication failures in an ordered event stream while rejecting ambiguous or oversized input.

Source, tests & run instructions ↗Current CI status ↗

Behavior you can inspect

Five failures for one principal inside a rolling 60-second window trigger an alert. Further alerts are suppressed until the window falls below the threshold. Success events are counted but do not erase preceding failures.

make test
make sanitize
./authlog < example.csv

Engineering decisions

Bound lines before allocation grows, validate integers without locale-dependent parsing, isolate per-account windows, and emit JSON only after the complete input passes validation. The restricted identifier grammar also prevents JSON injection.

Validation

10 black-box tests cover window boundaries, re-arming, malformed data, unsigned integer overflow, isolation and resource limits. Address/undefined-behavior sanitizer verification is documented in the validation record.

Scope

Offline defensive rule on synthetic events. No live ingestion, vendor parser, accuracy benchmark or production security claim.
