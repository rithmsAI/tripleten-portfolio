A house-price prediction service built around typed inputs, consistent model feature ordering, repeatable model loading, and interactive FastAPI documentation.

Educational case study. The published source is a separately reconstructed portfolio implementation based on the completed local coursework. The course-provided model artifact is not publicly redistributed, and this page is not a hosted prediction service.

Three endpoints. One coherent service.

GET /health

Report whether the saved model and metadata are loaded; signal an unavailable service.

GET /model/info

Return model version, training information, error metric and the exact 13-feature order.

POST /predict

Validate property inputs, order features as trained, and return a typed price prediction.

Engineering decisions

Keep the model in memory after startup instead of reading it from disk on every request. Order inputs using the same feature list used during training rather than relying on the order clients submit JSON keys. Separate request contracts, inference operations and HTTP routing, so failures can be diagnosed in isolation.
